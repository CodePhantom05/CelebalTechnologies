Retrieval-Augmented Generation (RAG) Notes

RAG is a technique that combines information retrieval with text generation.
Instead of relying purely on what a language model memorized during training,
a RAG system looks up relevant information from an external knowledge source
at answer time. This makes answers more factual and lets the system work
with private or up-to-date data the model was never trained on.

The typical RAG pipeline has three core stages: retrieval, augmentation, and
generation. In the retrieval stage, the system converts a user's question
into an embedding vector and searches a vector database for the most similar
document chunks. In the augmentation stage, those retrieved chunks are
inserted into the prompt as context. In the generation stage, a language
model reads the question plus the context and produces a final answer.

Chunking strategy matters a lot for retrieval quality. If chunks are too
large, irrelevant information dilutes the embedding and hurts precision.
If chunks are too small, important context can be split across chunks and
lost. A common starting point is 300-500 characters per chunk with a small
overlap between consecutive chunks so that ideas spanning a boundary are
not cut off.

Hybrid search combines dense vector similarity with sparse keyword search
methods like BM25. Vector search is good at matching meaning even when the
exact words differ, while keyword search is good at matching exact terms
like product names, IDs, or acronyms that embeddings sometimes blur
together. Combining both, often through reciprocal rank fusion, tends to
outperform either method alone.

Re-ranking is an optional extra stage where a more expensive but more
accurate model (often a cross-encoder) re-scores an initial set of
retrieved candidates. Because re-ranking only needs to score a small pool
of candidates rather than the entire corpus, it can afford to be slower
and more precise than the initial retrieval step.
